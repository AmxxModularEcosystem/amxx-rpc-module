# AGENTS.md — конвенции репозитория AmxxRpc

Инструкции для агентов и разработчиков, работающих в этом репозитории.

## Что это за проект

- **AmxxRpc** — транспортный **C++-модуль AMX Mod X** (Metamod-хук-модуль) для
  сервера CS 1.6 (HLDS/ReHLDS). Открывает внешним инструментам **JSON-RPC 2.0
  транспорт** (TCP loopback + токен) для команд, дебага, чтения состояния и
  управления **фейк-игроками** (тест-сценарии в игре).
- Модуль — **чистый транспорт**: он не знает про MCP и не связан с `amxb`. Каталог
  MCP-tools и MCP-протокол живут отдельно, в `amxb` (не в этом репозитории). Модуль
  предоставляет (а) встроенное ядро методов и (б) **нативы регистрации методов** для
  Pawn-плагинов; внешний мост мапит MCP-tools на RPC-методы.
- Парная поставка: сам модуль + публичный Pawn-инклюд `include/AmxxRpc.inc`
  (нативы регистрации) + пример плагина.
- Зависимости времени исполнения опциональны там, где это возможно (YAPB — только для
  навигации/ИИ ботов); см. `docs/09-dependencies.md`.

## Документация

- `docs/` — ТЗ (требования). Точка входа — [`docs/README.md`](docs/README.md).
- `docs/design/` — дизайн-документы подсистем. Индекс — [`docs/design/README.md`](docs/design/README.md).

### Требования и ID

- `AR-NNN` — архитектурные, `FR-<ОБЛАСТЬ>-NNN` — функциональные, `NFR-<КАТ>-NNN` — нефункциональные,
  `OQ-NNN` — открытые вопросы/допущения (`docs/08-open-questions.md`).
- Новые требования добавляются **в соответствующий документ `docs/*.md`**, а не в журнал.
- Дизайн-документы **ссылаются** на ID требований, не переписывают их.

### Язык

- Документация и комментарии — **на русском**. Промпты субагентам — на английском.
- `docs/07-jsonrpc-protocol.md` — **внешний wire-контракт** JSON-RPC (для агента `amxb`); менять
  его — только с обновлением версии `ARP_PROTO_VERSION` и этого дока.
- C++-код: имена — английские; комментарии — по необходимости русские/английские (не дублировать).

## Именование кода

### C++-модуль

- Подсистемы именуются **владельцем** (функции `PascalCase` с префиксом подсистемы):
  `Transport_*` (сокет/соединение/ключи), `Rpc_*` (JSON-RPC-диспетчер/реестр методов),
  `Protocol_*` (кодек/фрейминг), `Fake_*` (фейк-игроки), `Bot_*` (адаптер внешних ботов),
  `Config_*`, `Log_*`.
- Публичные C++-интерфейсы между подсистемами — узкие `struct`/функции в `src/`, не в SDK.
- Файлы — `PascalCase.{h,cpp}` (`Transport.h/.cpp`, `RpcRegistry.h/.cpp`, …).
- SDK (`amxxmodule.*`, `moduleconfig.h`) — **вендорится и не редактируется** (кроме
  `moduleconfig.h`, который правится по шаблону). См. `docs/conventions/cpp-module.md`.

### Pawn (публичный API)

- Публичные нативы — `ARpc_<Owner>_*` (`ARpc_Core_RegisterMethod`,
  `ARpc_Fake_Create`, …); обработчики — `@ARpc_*` (дефолтный стиль регистрации).
- Компиляционное время константы — `ARP_*` (`ARP_VERSION`).
- Теги типов — `T_ARpc_<Name>` + `Invalid_ARpc_<Name>` (см. `docs/conventions/amxx-pawn.md`).
- Команды — `amxxrpc_*`.
- Публичный инклюд — один файл `include/AmxxRpc.inc`.

## Сборка

- Сборка модуля — **CMake**, кроссплатформенно **Windows (MSVC, Win32) + Linux
  (`-m32`, multilib)**. См. `docs/design/` (build) и `docs/conventions/cpp-module.md`.
- Артефакты: `amxxrpc_amxx.dll` (Win) / `amxxrpc_amxx_i386.so` (Linux 32-bit),
  раскладка `addons/amxmodx/modules/`; инклюд — `addons/amxmodx/scripting/include/AmxxRpc.inc`.
- Активация модуля — строка `amxxrpc` в `addons/amxmodx/configs/modules.ini`.
- `USE_METAMOD` в `moduleconfig.h` — **обязателен** (нужны хуки движка: `StartFrame`,
  `GetPlayerAuthId`, `CreateFakeClient`). Следствие: тянем заголовки Metamod/HLSDK.

## Процесс разработки (feature-delivery)

Проект ведётся по **stage-gate** циклу (`feature-delivery`): дизайн → ревью дизайна →
вопросы владельцу → план → ревью плана → реализация → запись → коммит. Биндинги профиля:

- **Ревьюер дизайна** — `oracle`.
- **Ревьюер плана** — `momus`.
- **Дизайн-доки** — `docs/design/`, индекс `docs/design/README.md`.
- **Планы** — `.omo/plans/` (имя `NNNN-краткое-имя.md`).
- **Журнал** — `docs/journal/`, индекс `docs/journal/README.md`.
- **Open questions / принятые решения** — `docs/08-open-questions.md` (§ «Принятые решения»).
- **Верификация** — команды: сборка CMake (win/linux) 0 ошибок; загрузка модуля в HLDS
  без ошибок; smoke JSON-RPC (ping/version) по TCP; `amxxpc 1.10.5428` — 0/0 для инклюда и
  примера-плагина. Точные команды фиксируются в плане этапа.
- **Политика коммитов** — коммит **только по явному указанию владельца**, одним
  связным коммитом на этап.

### Обязательное правило: журнал разработки

**Цель журнала — преемственность между сессиями.** Новый агент по журналу должен понять,
что и почему происходило, и продолжить без перечитывания всего ТЗ. Запись
**самодостаточна по контексту** (этап, что сделано, развилки и почему, статус, что дальше),
но **не дублирует** требования/дизайн — ссылается на файлы и ID.

- Имя файла: `NNNN-краткое-имя.md` (сквозная нумерация, без дыр).
- Структура: **Дата · Этап · Статус**, Контекст, Сделано, Решения и обоснование,
  Открытые нити, Затронутые артефакты, Дальше.
- После записи — обновить индекс `docs/journal/README.md`.

## Анти-паттерны (blocking)

- Обращаться к AMXX/движку из I/O-потока (AMXX однопоточный). Только очередь → главный поток.
- Редактировать вендоренный SDK (`amxxmodule.*`) вместо `moduleconfig.h`.
- Логировать токен/секреты.
- Смешивать MCP-семантику в модуль (MCP — в `amxb`).
- Вводить обязательную зависимость от внешнего бота там, где нужна опциональность.
