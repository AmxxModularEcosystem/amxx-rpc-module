# 01. Архитектурные требования

## 1. Компоненты

| Компонент | Ответственность | Не знает о |
|---|---|---|
| `Transport_*` | Слушающий TCP-сокет, accept, соединения, токен-аутентификация, приём/отправка байт, фрейминг. | RPC-семантике, методах, движке. |
| `Protocol_*` | Разбор/сборка JSON-RPC 2.0 (запрос/ответ/нотификация), коды ошибок. | Транспорте, методах. |
| `Rpc_*` | Реестр методов, диспетчеризация, маршалинг запросов в главный поток. | Сокетах, деталях движка. |
| `Queue_*` | Мьютекс-защищённая очередь «I/O → main» и «main → I/O». | — |
| `Core_*` (методы) | Встроенное ядро: server.exec, cvar, players, logs/events, rpc.*. | Внешнем мосте. |
| `Fake_*` | Создание/удаление/управление фейк-игроками, подмена authid. | Транспорте, JSON-RPC. |
| `Bot_*` | Опциональный адаптер YAPB (dlopen `GetBotAPI`). | Обязательности YAPB. |
| `Config_*` | Чтение конфига (порт/токен/таймауты), reload. | — |
| `Log_*` | Логирование (без секретов). | — |

## 2. Потоки исполнения (жёсткое требование)

- **AR-001.** Модуль работает в **двух потоках**: один I/O-поток (сокет, парсинг) и
  главный поток сервера (AMXX/движок).
- **AR-002.** I/O-поток **никогда** не вызывает AMXX, нативы, движковые функции и не
  читает/не пишет игровое состояние. Он только принимает байты, парсит JSON, кладёт
  запрос в очередь и отправляет готовые ответы/нотификации.
- **AR-003.** Обработчики RPC-методов исполняются **только на главном потоке**.
- **AR-004.** Обмен между потоками — через мьютекс-защищённые очереди (`Queue_*`):
  запросы `I/O → main`, ответы и push-нотификации `main → I/O`.
- **AR-005.** Очередь запросов дренируется в **главном потоке** по метамод-хуку
  `StartFrame` (AMXX `FN_StartFrame`/`_Post`), с ограничителем частоты/размера.
- **AR-006.** Корректное завершение: на `OnAmxxDetach`/`Meta_Detach` — останов и join
  I/O-потока, закрытие сокетов, освобождение очередей. `detach()` без join запрещён.

## 3. Безопасность

- **AR-007.** Слушающий сокет по умолчанию — **только loopback** (`127.0.0.1`).
- **AR-008.** Каждое соединение обязано пройти **токен-аутентификацию** (общий секрет из
  конфига) до обработки любых методов.
- **AR-009.** Токен и секреты **не логируются** и не попадают в ответы.
- **AR-010.** Ограничения: максимум соединений, таймаут idle, максимальный размер сообщения,
  таймаут неответивших запросов, предельная глубина очередей (`docs/05`).

## 4. Расширяемость

- **AR-011.** Реестр методов: **встроенное ядро** + **регистрация Pawn-плагинами** через нативы.
- **AR-012.** Внешний вызов Pawn-обработчика инициируется модулем на главном потоке
  (форвард/колбэк); возврат результата — через публичный натив-API плагина.
- **AR-013.** Подписки: внешний клиент подписывается на именованные серверные события;
  модуль пушит нотификации.

## 5. Фейк-игроки

- **AR-014.** Создание — движковый `pfnCreateFakeClient` + `MDLL_ClientConnect`/
  `ClientPutInServer`; управление — `pfnRunPlayerMove`/usercmd.
- **AR-015.** Фейкам задаётся **собственная идентичность** (подмена `pfnGetPlayerAuthId`),
  т.к. движок отдаёт всем `"BOT"`.
- **AR-016.** Опциональный адаптер YAPB (навигация/ИИ) загружается динамически; при
  отсутствии YAPB модуль деградирует, а не падает.

## 6. Переносимость и сборка

- **AR-017.** Сборка — CMake, Windows (MSVC Win32) и Linux (GCC `-m32`); артефакты
  `amxxrpc_amxx.dll` / `amxxrpc_amxx_i386.so`.
- **AR-018.** `USE_METAMOD` обязателен (нужны движковые хуки). SDK вендорится, не редактируется.
- **AR-019.** Парная поставка: модуль + инклюд `AmxxRpc.inc` + пример плагина.

## 7. Функциональные требования

### Транспорт (`FR-TRANSPORT-*`)

- `FR-TRANSPORT-001` Слушать TCP на `127.0.0.1:<port>` (порт из конфига).
- `FR-TRANSPORT-002` Принимать несколько соединений (ограничено конфигом).
- `FR-TRANSPORT-003` Требовать токен; при неверном — закрывать соединение.
- `FR-TRANSPORT-004` Фрейминг: одно JSON-сообщение на строку (`\n`), без встроенных
  переводов строк; UTF-8.
- `FR-TRANSPORT-005` Максимальный размер сообщения и idle-таймаут (конфиг).
- `FR-TRANSPORT-006` Корректно переживать обрыв соединения и частичный приём (буферизация).

### RPC (`FR-RPC-*`)

- `FR-RPC-001` JSON-RPC 2.0: `request`/`response`/`notification`, коды ошибок.
- `FR-RPC-002` Методы ядра минимум: `rpc.ping`, `rpc.version`, `rpc.methods`.
- `FR-RPC-003` `server.exec` — исполнение серверной команды; `cvar.get/set`.
- `FR-RPC-004` `players.list` — состояние игроков (индекс, имя, authid, команда, здоровье, позиция).
- `FR-RPC-005` Подписка на события; в v1 — `player_connect`/`player_disconnect`/`map_start`
  и события от плагинов (`Emit`). `logs.tail` и раундовые/килл-события — **отложены** (`design/12` §12).
- `FR-RPC-006` Регистрация методов Pawn-плагинами; вызов и возврат результата.
- `FR-RPC-007` Валидация параметров и единый формат ошибок.
- `FR-RPC-008` `server.exec` исполняет команду и возвращает `{ok:true}`; захват вывода команды
  **отложен** в v1 (`design/12` §12).
- `FR-RPC-009` При **глобальной** выгрузке плагинов методы снимаются, pending-запросы завершаются
  ошибкой; `requestId` не переиспользуется. Индивидуальная выгрузка плагина в v1 надёжно не
  поддерживается (нет per-plugin хука; `design/12` §8).

### Фейк-игроки (`FR-FAKE-*`)

- `FR-FAKE-001` `fake.create` (имя, опц. authid) → индекс.
- `FR-FAKE-002` `fake.remove`.
- `FR-FAKE-003` `fake.move` (позиция/usercmd: forward/side/up).
- `FR-FAKE-004` `fake.look` (viewangles/на точку).
- `FR-FAKE-005` `fake.buttons` (нажать/отпустить, вкл. `IN_ATTACK`).
- `FR-FAKE-006` `fake.state` (health/armor/team/weapon/origin).
- `FR-FAKE-007` `fake.authid` — подмена авторида.
- `FR-FAKE-008` Покадровое поддержание фейков (RunPlayerMove/think) на главном потоке.
- `FR-FAKE-009` `fake.*` **отвергает индексы реальных игроков**; лимит числа фейков
  (не исчерпывать клиент-слоты).
- `FR-FAKE-010` Корректное удаление фейка (освобождение слота, снятие записи/авторида);
  отсутствие утечки слотов.
- `FR-FAKE-011` `fake.list`/`fake.get`/`fake.set`/`fake.stop` — реестр и состояние фейков.

### Боты (`FR-BOT-*`, опционально)

- `FR-BOT-001` `bot.available` — доступен ли YAPB.
- `FR-BOT-002` `bot.add`/`bot.goal`/`bot.look`/`bot.freeze` через YAPB `IBotModule`.
- `FR-BOT-003` При отсутствии YAPB — понятная ошибка, без падения.

### Конфиг/команды (`FR-CONF-*`)

- `FR-CONF-001` Конфиг: host/port, token, лимиты, таймауты.
- `FR-CONF-002` Серверные команды: `amxxrpc_reload`, `amxxrpc_status`.
- `FR-CONF-003` Fail-fast при невалидном конфиге.

## 8. Нефункциональные требования

- `NFR-SEC-001` Токен обязателен; loopback по умолчанию; секреты не логируются.
- `NFR-PERF-001` Главный поток не блокируется на I/O; очереди ограничены по размеру.
- `NFR-PERF-002` Накладные расходы StartFrame-дренажа — пренебрежимы при отсутствии трафика.
- `NFR-PORT-001` Windows (MSVC Win32) + Linux (`-m32`) из одного CMake.
- `NFR-PORT-002` Без обязательных рантайм-зависимостей; YAPB — опционален.
- `NFR-OBS-001` Структурные логи (без секретов); серверная команда статуса.

## 9. Анти-паттерны (blocking)

- Обращение к AMXX/движку из I/O-потока.
- Блокирующий приём на главном потоке (прямой `recv` без неблокирующего режима/потока).
- Обязательная зависимость от YAPB.
- Логирование токена.
- Смешивание MCP-семантики в модуль.
