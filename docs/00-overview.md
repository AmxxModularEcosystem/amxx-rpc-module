# 00. Обзор

## 1. Цели

- Дать внешним инструментам (в первую очередь AI-агенту через MCP-мост в `amxb`)
  **программный доступ к живому серверу CS 1.6**: выполнение команд, чтение состояния,
  дебаг, подписка на события.
- Дать **управляемых фейк-игроков** для сквозной проверки игровых сценариев без
  ручной игры: спавн, перемещение, прицеливание, стрельба, здоровье, команда.
- Дать Pawn-плагинам **регистрировать собственные RPC-методы** через нативы, чтобы
  любой плагин (например ExtendedStats) мог публиковать свои операции для агента.
- Быть **переносимым**: сборка и работа на Windows (MSVC/Win32) и Linux (`-m32`).

## 2. Область (scope)

### Входит

- C++-модуль AMX Mod X (Metamod-хук-модуль): TCP-транспорт, JSON-RPC 2.0, реестр методов,
  встроенное ядро методов, управление сервером/игроками/фейк-игроками.
- Публичный Pawn-инклюд с нативами регистрации методов и получения входящих вызовов.
- Пример Pawn-плагина, регистрирующего метод.
- Конфиг модуля, серверные команды, логирование.
- Сборка CMake win/linux, CI, раскладка артефактов.

### Не входит

- **MCP-протокол и каталог tools** — живут в `amxb`, вне этого репозитория.
- Игровая предметная логика (статистика, XP, режимы) — живёт в потребителях (Pawn-плагины).
- Написание внешнего моста MCP↔JSON-RPC — задача `amxb`.
- Обязательная зависимость от конкретного бота/движка.

## 3. Акторы

| Актор | Роль |
|---|---|
| **Внешний инструмент/агент** | Через MCP-мост вызывает RPC-методы: команды, состояние, фейк-игроки. |
| **MCP-мост (`amxb`)** | Вне этого репо. Гоняет байты stdio↔TCP либо мапит tools→methods. |
| **Pawn-плагин** | Регистрирует свои RPC-методы через нативы; может быть потребителем событий. |
| **Админ сервера** | Настраивает конфиг (порт/токен), использует серверные команды. |
| **Сервер HLDS/ReHLDS** | Процесс, в котором исполняется модуль; однопоточный. |

## 4. Глоссарий

- **Модуль** — `amxxrpc_amxx.dll` / `amxxrpc_amxx_i386.so`, загружается в AMXX.
- **Метод** — именованная операция JSON-RPC (`server.exec`, `rpc.ping`, `fake.create`, …).
- **Ядро (core) методов** — встроенный в модуль набор методов.
- **Реестр методов** — таблица «имя → обработчик (C++ или Pawn)».
- **Фейк-игрок** — движковый fake-client (`FL_FAKECLIENT`), управляемый извне.
- **Подписка** — регистрация внешнего клиента на серверные события (push-нотификации).
- **Токен** — общий секрет в конфиге; обязателен при подключении.

## 5. Среда исполнения

- HLDS/ReHLDS (GoldSrc), Counter-Strike 1.6, 32-бит.
- Metamod (1.21+) + AMX Mod X `1.10.5428`.
- Модуль загружается через `modules.ini`; использует `USE_METAMOD` (хуки движка).
- **Однопоточность:** AMXX и движок не потокобезопасны; сетевая работа — в отдельном
  I/O-потоке, исполнение в AMXX/движке — только на главном потоке (см. `01`, `03`).

- **AMXX module SDK** — `public/sdk/{amxxmodule.h,amxxmodule.cpp,moduleconfig.in.h}`,
  эталонные модули `sockets` (сеть), `mysqlx` (worker-поток + главный поток), `hamsandwich`.

- **ReHLDS** — `pfnCreateFakeClient`, `PF_GetPlayerAuthId`, `IRehldsHookchains`.
- **ReAPI** — `RG_CBotManager_OnEvent`, member-access, отсутствие bot-control нативов.
- **YAPB** — `IBotModule` (`GetBotAPI`), `SetBotGoalOrigin`/`SetBotLookAt`/`SetBotMovement`.
- **Prior art** — `goldsrc-query-mcp`, `rbash-mcp`, `ktox_claude_bridge`, `mcmorales/rcon-mcp-server`,
  `webserver_amxx`, `metamod-httpd`, `fastdl_mm`, `mschnitzer/sockets`.
- **CMake prior art** — ReAPI, AmxxEasyHttp, addtofullpack_manager, grip, fastdl_mm.
