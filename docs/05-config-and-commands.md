# 05. Конфиг, команды, логирование

## 1. Конфиг модуля

- Файл: `addons/amxmodx/configs/amxxrpc.cfg` (плоский `ключ = значение`, `#`/`;` — комментарии).
  (C++-модулю недоступен Pawn-модуль `json`; простой keyvalue читается нативно.)
- Поля:

| Ключ | Дефолт | Назначение |
|---|---|---|
| `host` | `127.0.0.1` | адрес bind (по умолчанию loopback) |
| `port` | `27016` | TCP-порт |
| `token` | — (обязателен) | общий секрет; пусто → модуль не поднимает транспорт (fail-fast) |
| `max_connections` | `4` | лимит одновременных соединений |
| `idle_timeout` | `120` | сек. до закрытия простаивающего соединения |
| `max_message_bytes` | `1048576` | лимит размера сообщения |
| `request_timeout` | `15` | сек., таймаут неответивших запросов |
| `inbox_depth` | `256` | предельная глубина очереди `I/O→main` (переполнение → `-32004`) |
| `outbox_depth` | `256` | предельная глубина очереди `main→I/O` (нотификации дропаются первыми) |
| `drain_budget` | `64` | сколько запросов обрабатывать за кадр (бюджет StartFrame) |
| `fake_max` | `8` | лимит числа фейк-игроков (`FR-FAKE-009`) |
| `yapb_path` | авто | явный путь к бинарю YAPB (опц.) |
| `log_level` | `info` | `error`/`warn`/`info`/`debug` |

- `token`: минимум 16 символов (fail-fast при короче); не логируется (`AR-009`).
- `host` вне loopback (не `127.0.0.1`/`::1`) — **предупреждение в лог** о cleartext-токене
  и снятой изоляции (`docs/08` R-4).
- `fake_think_interval` **удалён**: `RunPlayerMove` вызывается каждый кадр с `msec = frametime`
  (`docs/04` §4).

- **Fail-fast:** невалидный/отсутствующий обязательный конфиг → `Log` + модуль не поднимает
  транспорт (не «тихая деградация»), `FR-CONF-003`.
- Токен не логируется (`AR-009`).

## 2. Серверные команды

| Команда | Действие |
|---|---|
| `amxxrpc_reload` | перечитать конфиг (рестарт транспорта при смене порта/токена) |
| `amxxrpc_status` | состояние: listen/порт, число сессий, методов, фейков, YAPB |
| `amxxrpc_clients` | список аутентифицированных сессий (без токена) |
| `amxxrpc_help` | справка |

Регистрируются на главном потоке (`FN_AMXX_ATTACH`/boot). Реализация команд — через
движковый/AMXX addserver command (согласовать в дизайне).

## 3. Логирование

- Единый тег `AmxxRpc` (по образцу `MODULE_LOGTAG`).
- События жизненного цикла: старт/стоп транспорта, accept/close сессии, ошибки аутентификации
  (без токена), ошибки методов, состояние YAPB-адаптера.
- Секреты (токен) — **никогда**.
- `log_level` управляет детализацией.

## 4. Открытые детали (в дизайн-док)

- Формат файла конфига (keyvalue vs INI с секциями) и точный синтаксис комментариев.
- Перезагрузка «на лету» vs требование рестарта сервера/карты.
- Доступ к серверным командам (флаги админа vs rcon vs консоль).
