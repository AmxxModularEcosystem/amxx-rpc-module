# 04. Фейк-игроки

## 1. Цель

Управляемые «болванчики» для сквозной проверки игровых сценариев: спавн, перемещение,
прицеливание, стрельба, здоровье/броня/команда/оружие, собственная идентичность
(authid). Плюс — опциональный адаптер готового бота (YAPB) для навигации.

## 2. Движковый слой (создание/удаление)

Последовательность (подтверждено ReHLDS + yapb):

1. `g_engfuncs.pfnCreateFakeClient(name)` → `edict_t*` (занимает реальный клиент-слот;
   `NULL`, если слотов нет — `FR-FAKE-001`).
2. ключи userinfo через `pfnSetClientKeyValue` (имя, модель, цвета).
3. `MDLL_ClientConnect(ent, name, ip, reject)`.
4. `MDLL_ClientPutInServer(ent)`.
5. `ent->v.flags |= FL_FAKECLIENT | FL_CLIENT`.
6. регистрация записи фейка в реестре модуля (`index → FakeRecord`).
7. спавн (при необходимости) — движковой/`MDLL_Spawn`.

Удаление — движковый `remove`/`kick`-эквивалент + освобождение записи.

- **Удаление (детализировать в `design/13`):** корректное снятие — `MDLL_ClientDisconnect` и
  удаление эдикта; освобождение клиент-слота; снятие записи `FakeRecord` и буфера authid;
  без «висячих» эдиктов и утечки слотов (`FR-FAKE-010`).
- **Лимит:** число фейков ограничено (`fake_max`), чтобы не исчерпать клиент-слоты
  (`FR-FAKE-009`).
- **Защита:** `fake.*` **отвергает реальных игроков** — только индексы, зарегистрированные
  как фейки.

> Реализуется на главном потоке, под `USE_METAMOD` (`FN_CreateFakeClient`, DLL-funcs).

## 3. Идентичность и подмена authid

- Движок отдаёт всем фейкам `"BOT"` (`PF_GetPlayerAuthId` при `cl->fakeclient`).
- Подмена — хук движкового `FN_GetPlayerAuthId(edict_t*)`: для зарегистрированных
  фейков вернуть **свой** authid, иначе — обычное поведение.
  Канонический приём (yapb `linkage.cpp`): `RETURN_META_VALUE(MRES_SUPERCEDE, buf)`.
- Возвращаемая строка должна жить в постоянном буфере (per-fake storage); логика —
  на главном потоке.
- **Порядок:** authid задаётся **до** `MDLL_ClientConnect` (иначе первичная авторизация
  закэширует `"BOT"`). Хук обязан надёжно отличать фейка от реального игрока (по индексу +
  сверке записи), иначе возможно подмешивание чужого authid; после удаления фейка запись и
  буфер снимаются.
- Требования: `AR-015`, `FR-FAKE-007`.

## 4. Свой usercmd-слой (движение/прицел/стрельба)

- **Владелец контроля** — модуль, независимо от внешних ботов.
- Каждый кадр (главный поток, `StartFrame`) для каждого «живого» фейка вызывается
  `pfnRunPlayerMove(ent, viewangles, forwardmove, sidemove, upmove, buttons, impulse, msec)`
  с `msec = frametime` (не throttle по фиксированному интервалу — иначе рассинхрон с тиком
  и «залипание»). Без покадрового вызова фейк — «призрак» (нет bbox).
  Вызов только для живого/заспавненного фейка (guard от dead/not-spawned).
- Состояние фейка (viewangles, forward/side/up, зажатые buttons) хранится в `FakeRecord`
  и обновляется RPC-методами:
  - `fake.move` → forward/side/up;
  - `fake.look` → viewangles / на точку;
  - `fake.buttons` → нажать/отпустить (включая `IN_ATTACK` — выстрел);
  - `fake.stop` → сброс движения.
- Стрельба: `IN_ATTACK` в `buttons` (или `engclient_cmd("+attack"/"-attack")`).
- `msec` и интервал think согласованы с тик-рейтом, чтобы не «залипали» bbox.

## 5. Состояние

- `fake.state` (health/armor/team/weapon/origin/flags) и `fake.set` (health/armor/team/weapon).
- Запись/чтение — через edict/entvars на главном потоке.

## 6. RPC-методы подсистемы

| Метод | Назначение |
|---|---|
| `fake.create` | создать фейка (имя, опц. authid, команда) → индекс |
| `fake.remove` | удалить |
| `fake.list` / `fake.get` | состояние |
| `fake.move` / `fake.look` / `fake.stop` | движение/прицел |
| `fake.buttons` | кнопки (в т.ч. `IN_ATTACK`) |
| `fake.set` | health/armor/team/weapon |
| `fake.authid` | задать/прочитать authid |

## 7. Опциональный адаптер ботов (YAPB)

- Назначение — **навигация/«подойти»**, где нужен ИИ-обход; свои болванчики остаются
  для мишеней и точных сценариев.
- Загрузка динамическая: `dlopen`/`LoadLibrary` бинаря YAPB, resolve `GetBotAPI`,
  вызов `IBotModule::AddBot/SetBotGoalOrigin/SetBotLookAt/SetBotMovement`.
- При отсутствии YAPB — методы `bot.*` дают `-32002` (service unavailable), модуль работает.
- **Нет attack** в `IBotModule`: выстрел бота — через свой usercmd-слой (§4), а не через YAPB.
- `AR-016`; требования `FR-BOT-*`.

## 8. Ограничения (из ресёрча)

- authid у движковых фейков — `"BOT"` без подмены; подмена — через хук (§3).
- zBot (ReGameDLL) **не** имеет стабильного API (только Orpheu/server-cmd) — не используем
  как программный контроль.
- Фейки занимают реальные клиент-слоты.
- Движение/стрельба требуют покадрового драйва на главном потоке.

## 9. Открытые детали (в дизайн-док)

- Точный вид реестра `FakeRecord`, интервал think, лимит числа фейков.
- Нужен ли `MDLL_Spawn` и/или вызов `ClientPutInServer` для конкретных игровых режимов.
- Формат идентификатора фейка во внешнем API (индекс игрока vs own id).
- Соглашение о том, как `fake.*` сосуществует с реальными игроками (защита от управления ими).
